# 二次元可爱风论坛 · 开发计划（v1）

> 技术栈（已确认）：**Django 5.2 LTS + DRF + MySQL 8** ／ **Vue3 + Vite + TailwindCSS** ／ 前后端分离，JWT 鉴权 ／ 图片存**本地静态目录**
>
> **实现进度**：S1~S6 已完成（含评论、个人中心、换肤持久化），代码已跑在本机 MySQL `anime_forum` 上。第 7 节记录已实现接口清单与实测结论。

## 0. 关键设计决策（先对齐，避免返工）

| 决策点 | 选定方案 | 理由 |
|---|---|---|
| 用户表 | **自定义用户模型** `AUTH_USER_MODEL = 'users.User'` | 需要昵称、头像、简介、积分等字段；必须在**首次 migrate 前**落定 |
| 鉴权 | `djangorestframework-simplejwt`：Access(30min) + Refresh(7d)，放 `Authorization: Bearer` | 前后端分离标准做法，DRF 生态成熟 |
| 换肤实现 | **CSS 变量 + `<html data-theme="pink/blue/dark">`**，Tailwind 颜色映射到 `var(--*)` | 换肤只切属性、不重编译；暗黑系天然支持 |
| 换肤持久化 | 前端 `localStorage` 立即生效 + 登录后与 `themes_userpreference` 表双向同步 | 未登录也能换肤；登录后跨设备一致 |
| 点赞 | 单表 `target_type + target_id` + 唯一索引，`get_or_create` 防重复 | 一张表覆盖帖子/评论点赞，避免表爆炸 |
| 计数（赞/评论/浏览） | 写操作在事务内用 `F()` 原子自增；另提供 `recount` 管理命令兜底重算 | 避免读多写多的性能问题，同时能修漂移 |
| 图片存储 | `MEDIA_ROOT = backend/uploads/`，`MEDIA_URL = /media/`，文件名 uuid 化 | 后续换 OSS 只改上传函数，不动表结构 |
| UI 库 | **不引入 Element Plus / Ant Design**，自研「可爱风」组件（CuteButton / CuteCard / CuteInput） | 组件库默认样式与二次元卡通风格冲突，改造成本高于自研 |
| 前端语言 | TypeScript | 接口多、字段多，类型收益明显 |
| 软删除 | 帖子/评论 `status` 字段标记删除，分区用 `is_active` 停用 | 保留审计与恢复能力，避免外键 RESTRICT 报错 |

## 2. MySQL 数据库表结构设计

### 2.0 前置说明（很重要）

1. **不要手写 `django_*` / `auth_*` 系统表**。`django_migrations`、`django_content_type`、`auth_permission`、`auth_group`、`django_admin_log`、`django_session`，以及用户模型的 M2M 中间表 `users_user_groups`、`users_user_permissions`，全部由 `python manage.py migrate` 自动创建。手写会与 Django 的元数据不一致。
2. **下面的 DDL 是等价参考**，用途：DBA 评审 / 手动建库 / 理解字段设计。**权威来源是 ORM 模型 + migrations**，正式推进时以 `makemigrations` 生成的 DDL 为准（索引名、约束名会略有差异）。
3. Django 的删除语义由 `on_delete`（Python 层）实现，**DB 层不加 `ON DELETE CASCADE`**，与 Django 的建表行为保持一致，避免「应用层以为没删、数据库层已经级联」的双重语义。
4. 时间字段 Django 默认在 Python 侧写入，DDL 里的 `DEFAULT CURRENT_TIMESTAMP` 只是给手工插入用的便利默认值。
5. 环境要求：**MySQL ≥ 8.0.11**（Django 5.2 硬性要求）+ **utf8mb4**。
6. **本节 DDL 已按实际实现校准**（2026-10-19），权威脚本见 [init.sql](file:///c:/新建文件夹/trae/anime-forum/backend/scripts/init.sql)，可直接执行。与初版设计的三处差异：
   - `users_user.email` 改为可空（唯一索引允许多个 NULL，实现「邮箱选填但填了必须唯一」）；
   - `status` / `gender` 用 `SMALLINT` 而非 `TINYINT`（Django 无 TINYINT 字段类型映射，`SmallIntegerField` → `SMALLINT`）；
   - `forum_post`/`forum_comment`/`forum_likerecord` 的外键不建单列索引，改用复合索引前缀覆盖，避免同列重复索引拖慢写入（模型中通过 `db_index=False` 实现）。

### 2.2 用户表 `users_user`（继承 AbstractUser + 二次元扩展）

```sql
CREATE TABLE users_user (
  id             BIGINT       NOT NULL AUTO_INCREMENT,
  password       VARCHAR(128) NOT NULL,                 -- Django 哈希串（Argon2/PBKDF2）
  last_login     DATETIME(6)  NULL,
  is_superuser   TINYINT(1)   NOT NULL DEFAULT 0,
  username       VARCHAR(150) NOT NULL,                 -- 登录账号/唯一
  first_name     VARCHAR(150) NOT NULL DEFAULT '',
  last_name      VARCHAR(150) NOT NULL DEFAULT '',
  email          VARCHAR(254) NULL,                    -- 选填；MySQL 唯一索引允许多个 NULL
  is_staff       TINYINT(1)   NOT NULL DEFAULT 0,
  is_active      TINYINT(1)   NOT NULL DEFAULT 1,
  date_joined    DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6),

  -- 二次元扩展字段
  nickname       VARCHAR(30)  NULL,                     -- 展示昵称（可重复）
  avatar         VARCHAR(255) NULL,                     -- 相对路径 uploads/avatar/xxx.png
  bio            VARCHAR(200) NULL,                     -- 个性签名
  gender         SMALLINT     NOT NULL DEFAULT 0,       -- 0未知 1男 2女 3保密
  birthday       DATE         NULL,
  points         INT UNSIGNED NOT NULL DEFAULT 0,       -- 积分
  level          SMALLINT UNSIGNED NOT NULL DEFAULT 1,  -- 等级（由积分换算）
  last_login_ip  VARCHAR(45)  NULL,                     -- 兼容 IPv6
  updated_at     DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
                              ON UPDATE CURRENT_TIMESTAMP(6),

  PRIMARY KEY (id),
  UNIQUE KEY uk_users_username (username),
  UNIQUE KEY uk_users_email (email),
  KEY idx_users_nickname (nickname)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

> 注意：`email` 设了唯一约束，则「邮箱注册但昵称可重复」是成立的；若允许邮箱留空，需改成允许 NULL + 唯一（MySQL 中多个 NULL 不冲突）。

  UNIQUE KEY uk_board_name (name),

### 2.4 帖子表 `forum_post`

```sql
CREATE TABLE forum_post (
  id              BIGINT       NOT NULL AUTO_INCREMENT,
  board_id        BIGINT       NOT NULL,
  author_id       BIGINT       NOT NULL,
  title           VARCHAR(120) NOT NULL,
  summary         VARCHAR(255) NOT NULL DEFAULT '',     -- 摘要（留空则由正文自动截取）
  content         LONGTEXT     NOT NULL,                -- Markdown 原文（渲染在前端 + DOMPurify 消毒）
  cover_image     VARCHAR(255) NULL,
  images          JSON         NOT NULL,                -- 图集：[{"url":"...","w":800,"h":600}]
  status          SMALLINT     NOT NULL DEFAULT 1,      -- 1已发布 2已隐藏 3已删除 0草稿
  is_pinned       TINYINT(1)   NOT NULL DEFAULT 0,      -- 置顶（仅管理员）
  is_essence      TINYINT(1)   NOT NULL DEFAULT 0,      -- 精华
  view_count      INT UNSIGNED NOT NULL DEFAULT 0,
  like_count      INT UNSIGNED NOT NULL DEFAULT 0,      -- 冗余计数，事务内 F() 自增
  comment_count   INT UNSIGNED NOT NULL DEFAULT 0,
  last_comment_at DATETIME(6)  NULL,                    -- 列表按「最近活跃」排序用
  created_at      DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  updated_at      DATETIME(6)  NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
                               ON UPDATE CURRENT_TIMESTAMP(6),

  PRIMARY KEY (id),
  KEY idx_post_board_list (board_id, status, is_pinned, created_at),  -- 分区列表（置顶优先）
  KEY idx_post_board_active (board_id, status, last_comment_at),      -- 分区「最近回复」排序
  KEY idx_post_author (author_id, status, created_at),                -- 我的帖子
  KEY idx_post_hot (status, like_count, created_at),                  -- 热门榜
  KEY idx_post_title (title),                                         -- 关键词检索（量大再上全文索引）
  CONSTRAINT fk_post_board  FOREIGN KEY (board_id)  REFERENCES forum_board (id),
  CONSTRAINT fk_post_author FOREIGN KEY (author_id) REFERENCES users_user (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

> `content` 用 `LONGTEXT` 而非 `TEXT`：长文 + 图集 Markdown 容易超 64KB。
> 分区外键依赖外键约束，若担心性能可对 `board_id` 也建索引；`idx_post_board_list` 首列已是 `board_id`，已覆盖。

### 2.5 评论表 `forum_comment`（支持楼中楼）

```sql
CREATE TABLE forum_comment (
  id                BIGINT      NOT NULL AUTO_INCREMENT,
  post_id           BIGINT      NOT NULL,
  author_id         BIGINT      NOT NULL,
  parent_id         BIGINT      NULL,                   -- 一级回复为 NULL
  reply_to_user_id  BIGINT      NULL,                   -- 「回复 @某人」展示用
  content           LONGTEXT    NOT NULL,               -- 短文本，不支持复杂富文本
  like_count        INT UNSIGNED NOT NULL DEFAULT 0,
  status            SMALLINT    NOT NULL DEFAULT 1,     -- 1正常 3已删除（软删，保留子树结构）
  created_at        DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  updated_at        DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
                                ON UPDATE CURRENT_TIMESTAMP(6),

  PRIMARY KEY (id),
  KEY idx_comment_post (post_id, status, created_at),   -- 楼主评论流
  KEY idx_comment_parent (parent_id, created_at),       -- 楼中楼展开
  KEY idx_comment_author (author_id, created_at),
  KEY idx_comment_reply_to_user (reply_to_user_id),     -- 外键默认索引（启用了 SET_NULL）
  CONSTRAINT fk_comment_post   FOREIGN KEY (post_id)          REFERENCES forum_post (id),
  CONSTRAINT fk_comment_author FOREIGN KEY (author_id)        REFERENCES users_user (id),
  CONSTRAINT fk_comment_parent FOREIGN KEY (parent_id)        REFERENCES forum_comment (id),
  CONSTRAINT fk_comment_reply  FOREIGN KEY (reply_to_user_id) REFERENCES users_user (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

> 楼中楼建议**只做两级**（一级评论 + 二级回复），二级以下统一挂 `parent_id = 一级评论`，用 `reply_to_user_id` 表达「回复谁」。三级及以上会让前端渲染和分页复杂度陡增。
> 软删除的父评论：`status=3` 时前端渲染为「该评论已删除」，子回复仍可见。

### 2.6 点赞表 `forum_likerecord`

```sql
CREATE TABLE forum_likerecord (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  user_id     BIGINT      NOT NULL,
  target_type VARCHAR(10) NOT NULL,                     -- 'post' | 'comment'（Django choices 常量）
  target_id   BIGINT      NOT NULL,
  created_at  DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),

  PRIMARY KEY (id),
  UNIQUE KEY uk_like_once (user_id, target_type, target_id),  -- 一人一次，防重复点赞
  KEY idx_like_user_time (user_id, target_type, created_at DESC), -- 「我点赞过的帖」按时间分页
  KEY idx_like_target (target_type, target_id),                -- 聚合计数 / 查「谁赞过」
  CONSTRAINT fk_like_user FOREIGN KEY (user_id) REFERENCES users_user (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

> 关于 `target_id` 不做外键：因为同一列指向两张表，无法加单一外键。靠应用层保证一致性 + `recount` 命令兜底清理孤儿记录。
> 「我点赞过的帖」查询路径：`forum_likerecord(user_id=me, target_type='post')` → 批量取 `target_id` → `forum_post.id__in`，注意分页要按点赞时间去重排序（先分页 like，再取帖子，避免漏数据）。
